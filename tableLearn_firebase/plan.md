| ลำดับความสำคัญ | **จัดตารางให้ครบก่อน** — สอนแทนทำทีหลัง |

## 2. เป้าหมายและขอบเขต

### เป้าหมาย
1. ฝ่ายวิชาการจัดตารางทั้งโรงเรียน (≤18 ห้อง) **ได้ครบ ไม่มีชน** ภายใน 1–2 วันทำการ
2. ครูทุกคนเปิดดูตารางสอนของตัวเองได้ทันทีหลังประกาศ
3. พิมพ์เอกสารที่ใช้จริงได้ครบ: ตารางเรียนรายห้อง, ตารางสอนรายครู, ตารางรวม, ภาระงาน, ห้องพิเศษ, Excel
4. (เฟสถัดไป) จัดการสอนแทนรายวันพร้อมสถิติความเป็นธรรม

### อยู่ในขอบเขต
ข้อมูลพื้นฐาน · ภาคเรียน · โครงสร้างคาบ · ช่องล็อก · แผนการสอน · ตารางรายห้อง/รายครู/รายห้องพิเศษ · ตรวจชน · จัดอัตโนมัติรายห้อง · รายงาน · สิทธิ์ผู้ใช้ · สอนแทนตามวันที่

### ไม่อยู่ในขอบเขต (รอบนี้)
ครูสอนร่วม 2 คน · เรียนรวมหลายห้อง · ครูกำหนดวันไม่ว่างรายคน · นักเรียน/ผู้ปกครองดูแบบสาธารณะ · คัดลอกแผนข้ามเทอม · เรียนวันเสาร์ (ดูข้อ 13 Backlog)

## 7. กฎการจัดตารางและตัวจัดอัตโนมัติ

### 7.1 เงื่อนไขบังคับ (Hard) — ฝ่าฝืนไม่ได้ทั้งจัดมือและอัตโนมัติ
| รหัส | เงื่อนไข |
|---|---|
| H1 | ชั้นเรียนหนึ่งช่องมีได้ 1 รายการ (บังคับด้วย doc ID) |
| H2 | ครูสอนได้ครั้งละ 1 ชั้น (รวมช่องล็อกที่ระบุครูผู้ดูแล) |
| H3 | ห้องพิเศษใช้พร้อมกันไม่เกิน `capacity` |
| H4 | ห้ามวางทับช่องล็อกของชั้นนั้น |
| H5 | วิชาในวันเดียวไม่เกิน `maxPerDay` |
| H6 | คาบคู่ต้องอยู่ติดกันในวันเดียว และไม่คร่อมพักกลางวัน |
| H7 | ครูสอนต่อวันไม่เกิน `maxPerDay` และต่อสัปดาห์ไม่เกิน `maxPerWeek` |
| H8 | ครูสอนติดกันไม่เกิน `maxConsecutive` คาบ |
| H9 | จำนวนคาบที่จัดของแต่ละแผน ≤ `periodsPerWeek` |

> การจัดมือ: H1–H4 **บล็อก** · H5–H9 **เตือนแบบยืนยันได้** (แอดมินมีเหตุผลพิเศษได้) และไปแสดงในหน้า "รวมปัญหา"

### 7.2 เงื่อนไขพึงประสงค์ (Soft) — ใช้ให้คะแนนตำแหน่ง
| รหัส | เงื่อนไข | น้ำหนักเริ่มต้น |
|---|---|---|
| S1 | กระจายวิชาให้ไม่อยู่วันเดียวกัน/วันติดกัน (วิชา ≤3 คาบ/สัปดาห์) | สูง |
| S2 | `preferredTime` ตรง (วิชาหลักไว้ช่วงเช้า) | กลาง |
| S3 | `avoidAfterLunch` (พลศึกษาไม่อยู่คาบแรกหลังพักกลางวัน) | กลาง |
| S4 | ครูมีพักกลางวันอย่างน้อย 1 คาบ | สูง |
| S5 | ภาระครูแต่ละวันสม่ำเสมอ ช่องว่างระหว่างคาบไม่มากเกินไป | ต่ำ |

### 7.3 ตรวจความพร้อมก่อนจัด (Feasibility check) — แก้ A10
แสดงเป็นแผงในหน้าแผนการสอนและก่อนกดจัดอัตโนมัติ:
- รายชั้น: `คาบตามแผนรวม` เทียบ `ช่องว่างหลังหักช่องล็อก` (เกิน = แดง)
- รายครู: ภาระรวมทุกชั้นเทียบกับ `maxPerWeek` / `minPerWeek`
- รายห้องพิเศษ: คาบที่ต้องใช้เทียบกับความจุ (`ช่องทั้งหมด × capacity`)
- คาบคู่: มีช่องติดกันที่ไม่คร่อมพักเพียงพอหรือไม่

### 7.4 อัลกอริทึมจัดรายห้อง (แทน `autoGenerateSchedule` เดิม)
1. **สร้างหน่วยที่ต้องจัด**: แต่ละแผน → คาบคู่ `doubles` หน่วย (ขนาด 2) + คาบเดี่ยวที่เหลือ หักส่วนที่จัดไว้แล้ว
2. **ลบเฉพาะส่วนที่ไม่ล็อก** (โหมด "จัดใหม่") หรือ **คงของเดิม** (โหมด "เติมช่องว่าง")
3. **เรียงหน่วยแบบเงื่อนไขแน่นสุดก่อน** (most-constrained first): คาบคู่ → ใช้ห้องพิเศษ → ครูภาระสูง → ตำแหน่งที่วางได้น้อย
4. **ค้นหาแบบย้อนกลับ (backtracking) + forward checking**: ลองตำแหน่งเรียงตามคะแนน Soft ถ้าทางตันให้ถอยกลับ
5. **จำกัดเวลา ~3 วินาที + เริ่มใหม่แบบสุ่มหลายรอบ** เก็บคำตอบที่ดีที่สุด (จัดได้มากสุด → คะแนน Soft สูงสุด)
6. **แสดงตัวอย่างก่อนบันทึก** (ช่องโปร่งแสง) → กด "ยอมรับ" → บันทึกด้วย `writeBatch` ครั้งเดียว · "ลองใหม่" ได้คำตอบอื่น
7. **รายงานสิ่งที่จัดไม่ได้พร้อมเหตุผล** เช่น *"ว21102 (ครูสมศรี) เหลือ 1 คาบ: ช่องว่างของห้องตรงกับเวลาที่ครูติดสอน 5 ช่อง, ติดห้องคอมเต็ม 2 ช่อง, เกินคาบ/วัน 3 ช่อง"*
8. ปุ่มเสริม **"จัดทุกห้องต่อเนื่อง"**: วนจัดรายห้องตามลำดับความยาก (ชั้นที่ใช้ครูเฉพาะวิชามากก่อน — มักเป็น ม.ต้น) เพื่อลดปัญหาห้องที่จัดทีหลังเหลือช่องไม่ดี โดยยังคงหลักการจัดทีละห้อง

> ตัวจัดเป็นฟังก์ชันบริสุทธิ์ `solve(input) → { placements, unplaced[], score }` ใช้ `lib/rules.ts` ตัวเดียวกับการจัดมือ — กฎจึงตรงกันเสมอ

### 9.2 การสอนแทน (เฟส 4)
1. แอดมินบันทึก **การลา**: ครู + ช่วงวันที่ + ทั้งวัน/บางคาบ + ประเภท
2. ระบบสร้างรายการคาบที่ต้องแทนอัตโนมัติจากตารางหลัก (ข้ามวันหยุดใน `terms.holidays`)
3. แต่ละคาบแสดง **ครูที่แนะนำ** โดย
   - เงื่อนไขบังคับ: ว่างคาบนั้นทั้งในตารางหลักและในการสอนแทนวันนั้น, ไม่ลาวันนั้น, รวมคาบวันนั้นไม่เกิน `maxPerDay`
   - เรียงลำดับ: **สอนแทนสะสมในเทอมน้อยสุด** (ความเป็นธรรม) → กลุ่มสาระเดียวกัน/เคยสอนชั้นนี้ → คาบวันนั้นน้อยกว่า
   - แสดงเหตุผลประกอบ เช่น "สอนแทนแล้ว 2 ครั้ง · กลุ่มสาระเดียวกัน · วันนี้สอน 3 คาบ"
4. แอดมิน **เลือกตามคำแนะนำ หรือเลือกครูว่างคนอื่นเอง** หรือ "มอบงาน (ไม่มีผู้แทน)"
5. เอกสาร: **ใบแจ้งสอนแทนประจำวัน** (มีช่องลงชื่อรับทราบ), สถิติรายเดือน/ภาค รายครู
6. ตารางรายชั้น/รายครูมีตัวเลือก **"ดูตามวันที่"** เพื่อแสดงการแทนของวันนั้น โดยไม่แก้ตารางหลัก (แก้ A8)

## 11. การทดสอบ

## 12. ความเสี่ยงและคำถามที่ต้องยืนยันเพิ่ม

### ความเสี่ยง
| ความเสี่ยง | ระดับ | การรับมือ |
|---|---|---|
| เวลาเหลือ ~3 สัปดาห์ แต่ต้องเขียนใหม่ด้วย React | **สูง** | ตัดขอบเขต MVP เฟส 0–3 ชัดเจน, มี Plan B |
| ข้อมูลจริงยังไม่ได้กรอก | สูง | เริ่มเก็บรายชื่อครู/วิชา/แผนจากหัวหน้ากลุ่มสาระตั้งแต่สัปดาห์นี้ |
| แผนการสอนเป็นไปไม่ได้ (ครูไม่พอ) | กลาง | แผงตรวจความพร้อมตั้งแต่เฟส 1 |
| ตัวจัดรายห้องทำให้ห้องหลัง ๆ จัดยาก | กลาง | เรียงลำดับห้องตามความยาก + ล็อกและจัดซ้ำได้ |
| Firebase โควตาฟรี | ต่ำ | ข้อมูลเล็ก (≤18 ห้อง) ใช้ Spark plan ได้สบาย |

### คำถามที่ต้องยืนยัน (ไม่บล็อกการเริ่มเฟส 0)
1. เวลาคาบจริงของโรงเรียน และพักกลางวันของแต่ละช่วงชั้นอยู่คาบใด
2. รายชื่อห้องพิเศษ และวิชาใดบ้างที่ต้องเป็นคาบคู่/ใช้ห้องพิเศษ
3. ค่าเริ่มต้น: ครูสอนสูงสุดกี่คาบ/วัน กี่คาบ/สัปดาห์ ติดกันไม่เกินกี่คาบ และเกณฑ์ขั้นต่ำต่อสัปดาห์ (ตรวจกับเกณฑ์ ก.ค.ศ./PA ฉบับปัจจุบัน)
4. หัวหน้ากลุ่มสาระแก้ "แผนการสอน" ได้อย่างเดียว (ตามที่ออกแบบไว้) หรือต้องแก้ตารางได้ด้วย
5. วันเปิดเทอม 2/2569 และวันหยุดในภาคเรียน
6. ชื่อผู้ลงนามในรายงาน และไฟล์ตราโรงเรียน
